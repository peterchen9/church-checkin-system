# 主日聚會與條碼列印

## 已完成的行政平台功能

主日專用入口已依需求保留原報到畫面及操作流程，直接顯示主日掃碼畫面；右側「手動搜尋報到」下方內嵌同寬的列印搜尋區，上方獨立列印按鈕已移除。保留原版樣式、全螢幕、相機掃碼、鍵盤式掃碼、手動搜尋與多人選擇視窗；後端資料仍串接行政平台。

- 主日專用入口：`/eureka/sunday/`。
- 條碼列印入口：`/eureka/sunday/barcodes/`。
- 使用行政平台登入及既有通訊錄權限，不使用舊報到後台的獨立密碼。
- 姓名、手機、住家電話或辦公電話搜尋；顯示電話尾碼供核對。
- 掃描活石條碼或選擇搜尋結果後報到。
- 主日紀錄與通訊錄 presence 狀態在同一筆交易寫入；首次打卡日期空白時補上。
- 相同人員、同日、同堂次不重複寫入，紀錄保留操作帳號與時間。
- 人員詳情的「出席狀態」顯示最近 12 筆新主日紀錄，原有歷史圖保留。
- 標籤採方形 QR Code，QR Code 固定 20 × 20 mm，下方以 2 mm 字體印出完整姓名，不印編號文字；每次產生同一人 3 張相同標籤，使用電腦已安裝的條碼機驅動。

## 活石條碼相容規則

已直接查驗 8002 舊系統的 `check_in/views.py:to_nghc_id()`：內容為 `NG` 加 6 位 church_id，再加 3 位檢查碼。以這前 8 字元計算 MD5，取十六進位前 7 碼轉成整數後取模 1000，再補零成 3 位。例如編號 123 為 `NG000123708`。新系統生成與掃碼驗證均使用此算法，NG 大小寫皆接受；純數字人員編號仍可使用。舊版新系統曾產生的固定 000 尾碼若不符合檢查碼，需重新製卡。

舊列印透過 Windows `EZio64.dll` 對 USB 標籤機送出指令，先印姓名電話，再印 6 張 QR 標籤。新系統目前採已安裝印表機驅動的瀏覽器列印，每次 3 張 QR 標籤；Linux Docker 無法直接使用該 Windows DLL，直接 USB 列印仍需 Windows 列印端。

無法以電話或姓名自動推算活石編號；需確認舊卡中的 church_id 與行政平台同一人相符。超過 6 位的人員編號不會強行截短列印。

## 列印流程

1. 搜尋姓名或電話，核對人名、牧區及小組。
2. 搜尋結果只顯示人名／牧區／小組；標籤固定使用預設 25.4 × 25 mm，不顯示尺寸設定欄。
3. 按右側「直接列印」，以同網站背景 iframe 載入 3 張標籤，不另開分頁；列印流程結束（afterprint）後清空搜尋欄與結果，焦點回到掃碼欄。取消列印也會觸發清除，不能據此判定出紙成功。
4. 使用 Chrome 專用啟動檔開啟可自動確認列印；預設條碼機份數設 1（頁面已含 3 張）、縮放 100%、關閉頁首頁尾。

瀏覽器列印無法保證或回報實際出紙成功。印表機型號、紙張尺寸、列印驅動及掃描器仍須現場測試；初次請確認預覽為 3 頁，再用測試標籤校正。

## 驗證與範圍

13 項隔離 SQLite 測試通過，涵蓋條碼解析、電話搜尋與遮罩、未登入限制、非主日測試開放及限制恢復、去重、失敗回復、三張標籤、時間邊界及 CSRF。正式環境已驗證頁面渲染、通訊錄唯讀搜尋及標籤輸出；未寫入正式人員測試出席。

本次新增的是行政平台原生主日流程，不依賴故障中的舊 PHP 資料庫連線。舊系統的其他聚會、課程及同工打卡模式尚未遷移；舊出席率彙總及歷史圖未重新計算。

原報到首頁的主日聚會與列印條碼按鈕已完成 sudo 安裝，並驗證首頁、轉接頁 HTTP 200 及導向網址正確。

## 暫時開放非主日測試

已暫停僅週日可報到的限制，保留同人同日同堂次去重。測試報到仍寫入正式出席紀錄及通訊錄狀態。測試完成後需將 sunday_views.py 的 SUNDAY_ONLY 恢復 True 並重新載入平台。


## Chrome 靜默列印

列印電腦將標籤機設為 Windows 預設印表機，驅動紙張設為 25.4 × 25 mm、100% 縮放、份數 1。執行 scripts/start-label-printing.cmd，以獨立 Chrome 使用者目錄及 --kiosk-printing、--use-system-default-printer 啟動。首次需登入平台；以後均由此啟動檔開啟。Chrome 會自動確認列印，可能短暫顯示預覽；網頁本身無法保證完全沒有視窗閃現。尚需現場驗證實際出紙。

## 2026-10-24 設定快照

- 紙張預設：25.4 × 25 mm；QR Code 20 × 20 mm（含四模組留白），ReportLab，M 級錯誤更正。
- 姓名字體：2 mm，行高 1；與 QR 間隔 0.5 mm；標籤內距上下 1 mm、左右 2 mm。
- 每次固定 3 張；搜尋頁不提供尺寸設定。後端仍接受 width（25–100）及 height（25–80）參數，預設如上。
- 搜尋顯示人名／牧區／小組；電話僅供搜尋，不顯示在列印搜尋結果。
- 列印頁限定 X-Frame-Options: SAMEORIGIN；其餘平台安全設定保留。背景文件空值或載入錯誤時保留搜尋結果，可重試。
- 列印進行中鎖住操作避免重複送印；afterprint 後重設。瀏覽器不能確認實體出紙，也無法由網頁強制開啟靜默列印。
- 主日限制目前 SUNDAY_ONLY=False（暫時測試）；堂次第一堂 07:30–10:15:59、第二堂 10:16–13:00:59、晚崇拜 18:00–21:30:59，其餘為主日其他時段；Asia/Taipei。
- 原始列印設備的 Windows DLL 直連未啟用，現行採瀏覽器與已安裝的印表機驅動。
- 測試：13 項 Django 隔離 SQLite 測試；node integration/nads26/test_label_print.cjs 驗證背景列印、重複點擊、空文件與錯誤回復。現場出紙尚待確認。

## 原始碼與部署限制

本儲存庫保存新主日功能、模板、測試、入口轉接及部署腳本；不含行政平台完整原始碼、正式資料庫、帳密或 SSH 金鑰。integration/nads26/apply_integration.py 為首次整合工具，含原始版本雜湊檢查，不適合直接在已更新平台上重跑；更新時先備份並核對版本，再同步對應檔案與重新載入 nads26-web。正式位置 /home/apps1/nads26，容器 /app 掛載此目錄，服務 26001。
